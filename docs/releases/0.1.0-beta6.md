# PocketUFW 0.1.0-beta6

Local unsigned release candidate for independent review. Package
`io.github.pocketufw`, versionCode **27**. No signing, installation, tag or
publication is part of this preparation.

## Changes

- **Insights v1:** manually sample up to ten seconds or 256 DROP records, with
  physical/tunnel and IPv4/IPv6 breakdowns, sources, protocols and traffic clues.
  Metadata stays in memory; no background collection, payload log or DNS lookup.
- **Audited native safeguards:** bounded root operations, exact probe ownership
  and cleanup, lock/process lifetime safeguards, strict result parsing and narrow
  recovery. Failed or withheld collections independently verify ACTIVE after
  successful cleanup; the UI requires a fresh protection check.
- **Quieter recovery:** healthy Insights keeps recovery under Troubleshooting;
  detected reserved probe residue promotes recovery. Malformed probes require
  manual review and are never broadly removed or repaired.
- **Tide cleanup:** Activity is the single home for counters. The Statistics
  dropdown and Insights' duplicate historical summary are removed. Physical
  IPv4/IPv6 reply counts are always visible, matching tunnel counts; refresh,
  reset, values and verification safeguards are preserved.
- **Carrier IMS wording:** only corroborating Android network records identify
  system-managed carrier calling interfaces. The uncovered-interface warning
  remains; an `ipsec*` name alone proves nothing. Android back-navigation opt-in
  addresses the app warning. The Moto QTI display-property SELinux denial is
  documented as vendor behavior, with no permission or SELinux workaround.

The firewall engine, tunnel policies, UDP exceptions and boot behavior are
unchanged from Beta 5. `rules-report` only increases its bounded tunnel listing
allowance to expose temporary Insights probes; it does not change enforcement.

## Known limitations

- **Android/OEM filter-rule changes can cause Insights to withhold a sample.**
  Full IPv4/IPv6 filter-table comparison remains strict, apart from numeric
  quota2 countdown state. Cleanup and independent protection verification still
  run after a refused collection. Qualified sampling and carrier-churn
  acceptance exceptions remain unimplemented pending independent proof.
- Samples are bounded and can lose records; they cannot explain historical
  totals, identify applications or establish malicious intent. Kernel NFLOG
  support is required. Forceful termination can leave nonterminating logging
  probes ahead of intact DROP rules; exact recovery remains necessary.
- ACTIVE verifies PocketUFW's configured rules, not universal interface coverage.
  Earlier Android/OEM accepts and unsupported interfaces remain limitations.
  [IPsec inner-interface coverage](../ipsec-inner-interface-coverage.md) is an
  open, separate issue; IMS attribution does not make that traffic filtered.
- Earlier Moto capture/cancellation/crash-recovery tests passed. Frankenpixel's
  earlier code-26 installation stayed ACTIVE/PINNED/MATCH, but its supervised
  capture was withheld during carrier rule churn. Displayed capture results and
  unsolicited WireGuard-inner blocking were not verified there. **This final
  Beta 6 APK has not been installed or device-tested.**

## Update and rollback boundary

Future installation requires independent review and signing with the existing
PocketUFW release identity. The package ID is unchanged and code 27 is newer
than Beta 5/code 26; a compatible signed in-place update should retain app data.
Installation does not replace live firewall policy or enable boot restoration.

Preserve the original signed Beta 5 rollback APK. Code 27 means that ordinary
replacement with the older code-26 APK is a downgrade and may be rejected;
the historical same-code Insights test rollback procedure does not apply.
Any rollback strategy requires separate review. Do not uninstall, clear data,
reset protection or force a downgrade as an automatic fallback.

## Unsigned build

Use Java 17, Android SDK/platform 36, Build Tools 34.0.0, NDK 27.2.12479018,
CMake 3.22.1 and the checked-in Gradle 8.9 wrapper (AGP 8.7.0, Kotlin 1.9.22).
Use Build Tools 36.0.0 for the 16 KiB `zipalign -P 16` verification below;
the Gradle build itself uses AGP's default Build Tools 34.0.0.
Set `ANDROID_HOME` to the SDK. With dependencies already cached:

```sh
cd android
./gradlew --offline --no-build-cache --max-workers=2 :app:assembleRelease
```

Output: `android/app/build/outputs/apk/release/app-release-unsigned.apk`.
No release signing configuration is defined. Verify the manifest identity,
ZIP integrity, `zipalign -c -P 16 4`, and the absence of APK signatures before
handing the immutable artifact to the signing owner. Do not use a debug APK.

For reproducibility, build the same source in two fresh checkout directories
with the same toolchain and no copied build outputs, then compare APK SHA-256
and bytes. Native compiler debug paths are normalized so checkout and NDK
locations do not change ELF build IDs; no native capture logic is changed.
The candidate evidence records the exact toolchain, commands, source
manifest, test logs, unsigned APK and checksums separately from source control.
