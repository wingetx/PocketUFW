# PocketUFW 0.1.0-beta8.1 🐧

**Android 8.0+ · Root required · versionCode 31 · Experimental prerelease**

The APK is signed with the existing PocketUFW release identity. Historical [Beta8 release notes](0.1.0-beta8.md) remain unchanged.

## What's changed

- **Swipe navigation:** swipe horizontally through Firewall, Activity, Insights, and Settings in bottom-navigation order. Each tab retains its scroll/disclosure state, and navigation does not restart root work or cancel an active Insights sample. Swipes starting over clickable rows cancel the pending tap and navigate. Vertical scrolling, child drag controls such as raw-rule scrolling, and Android's back-gesture edges retain priority. The UDP editor remains a separate subpage.
- **Tide cleanup:** the collapsed Termux dropdown no longer has a redundant divider. The main Firewall screen's Restore after reboot shortcut is removed; its Settings toggle and behavior remain. Settings no longer has a standalone REMOVE heading; the Remove PocketUFW row, warning, confirmation, and removal behavior remain.
- **`pufw clear`:** type `yes` to reset PocketUFW-owned counters through the same `android-bridge reset-counters` action as Activity → Reset counters. Other answers and end-of-input cancel before root is requested. No `--yes` option, automatic retries, or background work is added. The command is available to tap and copy in Termux quick commands.
- **Shared reset time:** successful app and CLI resets atomically save the reset time in the app-private engine directory. Refresh counters or Recheck updates the app's Last manual counter reset display. Legacy app preferences remain a fallback. Missing root, busy/degraded state, incomplete output, timeout, and timestamp-write failure are reported rather than silently treated as success; some counters may already have reset when a later step fails.

Only owned physical, Tailscale-child, and installed tunnel counters are reset. Rules, filtering policy/state, tunnel pins and authorization, UDP exceptions, and boot opt-in remain unchanged. Packets may increment counts immediately after reset. The latest Insights sample is held in app memory; there is no persistent sample-history database, and counter reset does not clear that sample or exported/standalone records. [Termux instructions and failure behavior](../termux.md).

The firewall engine and packet-filtering/tunnel authorization policies are unchanged from Beta8. The privileged bridge changes only counter-reset timestamp metadata and reporting; the bundled Termux helper adds the confirmed reset command.

## Existing security and compatibility limitations

- **Wi-Fi calling:** incoming calls failed on a Pixel 9a running Android 17 when physical filtering was enabled and the carrier's UDP 4500 connection-tracking entry was absent. Calls succeeded with filtering off or the entry present. **If you rely on Wi-Fi calling, do not enable physical filtering until this is fixed.** Disabling Wi-Fi calling is a workaround only with reliable cellular reception. Other devices/carriers and SMS have not been tested.
- **ACTIVE is a point-in-time rule/hook verification, not universal traffic coverage.** Earlier Android/OEM ACCEPT rules and unsupported interfaces, including carrier IPsec inner interfaces and tethering paths, can bypass physical hooks. Outbound policy remains Android's responsibility.
- **PINNED verifies destination addresses, not cryptographic packet origin.** Another `tun*` interface may inject traffic aimed at a pinned destination. Tunnel filtering does not restore after reboot; optional physical boot restoration is separate. Manual recheck/refresh is required when relevant listeners or addresses change; there is no background VPN monitor or automatic repair.
- **Insights is bounded, on demand, and diagnostic.** It does not identify attackers or continuously monitor traffic. Android/OEM changes may cause a sample to be withheld after cleanup. Raw packet bytes are not saved.
- Use **Settings → Remove PocketUFW** before uninstalling. Ordinary Android uninstall can leave live rules until reboot, and slow boot can delay hook cleanup.

Root and compatible `iptables`/`ip6tables` are required. PocketUFW remains experimental and does not replace Android's security protections.

## Release validation

- **401 Android JVM/Robolectric tests passed**, including swipe/control conflicts, retained tab/sample state, removal confirmations, helper installation/copying, and reset-time parsing.
- **Release lint passed:** 0 errors, 3 existing warnings (target API, obsolete SDK check, unused resource), and 2 informational findings. A clean unsigned release build succeeded.
- **Full Python suite: 721 tests run, 700 passed, 21 skipped, no failures** (494.9 seconds). All skips require an unavailable AOSP `mksh` host build; Android-shell-specific behavior is not covered by this run. The suite includes 38 helper/clear checks and isolated real-kernel regressions.
- The two formerly failing Python checks were obsolete assertions: one required Beta6/versionCode 27; the other required the pre-Beta8 inline headline implementation. The metadata check now follows the current version's changelog/release notes. The UI check follows `TideProtectionStatus`, uncertainty precedence, and the guarded Recheck action. Production behavior was not changed to satisfy either test.
- All seven packaged firewall scripts and `assets/termux/pufw` match their intended source bytes/SHA-256 hashes. No discrepancies were found. The six policy/support scripts remain identical to Beta8; the bridge and helper contain the approved reset metadata/command changes. Font-license assets also match their sources.
- The manifest reports versionName `0.1.0-beta8.1`, versionCode 31, and a non-debuggable release. The signed APK verifies with signature schemes v2/v3, correct release identity and 16 KiB ZIP alignment. Signing credentials remained outside the worktree.
- **Earlier device validation:** four native-input tests and navigation through all four tabs in both directions passed on Frankenpixel (Pixel 9a, Android 17) with the Beta8 polish debug build. These tests used a debug-signed build, not the release-signed artifact.

**Live device follow-up:** on Frankenpixel, the updated Termux helper successfully ran confirmed `pufw clear` and reported a saved reset time; after Refresh counters, the app displayed the matching 9:18 PM manual reset (November 13, 2026). This was verified on the Beta8 polish debug build, not the release-signed APK. System Back in gesture-navigation mode still needs a spot-check; prior native tests used three-button navigation. The existing Wi-Fi calling incompatibility and security limitations above remain unresolved.

`29cac70ee30ed8ab26676aeb60809bdf668f3ad3428eab556316970ce1f99ad2`

Release-signed installations can update in place using this APK. A debug-signed APK cannot be updated in place with the release certificate. On a debug installation, turn off PocketUFW and verify rule cleanup before uninstalling and installing the signed build.

After installing the signed APK, open PocketUFW and tap Recheck. To get `pufw clear`, copy a fresh command from Firewall → Termux quick commands → Install the helper and run it in normal Termux. Installation is rootless; running the helper requires root. The older Beta8 helper does not acquire new commands automatically.
