# PocketUFW 0.1.0-beta8 🐧

**Android 8.0+ · Root required · versionCode 30 · Experimental prerelease**

Beta8 focuses on clearer feedback, safer explanations, and an optional Termux companion. The seven privileged firewall scripts, inbound rules, VPN exception policy, and Magisk boot behavior are unchanged from Beta7.

## Important: Wi-Fi calling compatibility

**Confirmed incoming-call failure on a Pixel 9a running Android 17:** when Wi-Fi calling is enabled, PocketUFW's physical firewall can silently block incoming calls after the carrier's UDP 4500 connection-tracking entry expires. Calls succeeded with PocketUFW disabled or the entry present, and failed with the firewall enabled and the entry absent.

**If you rely on Wi-Fi calling to receive calls, do not enable PocketUFW's physical firewall until this is fixed.** Turning Wi-Fi calling off is a workaround only when cellular reception is reliable. Other phones/carriers and the effect on SMS have **not** been tested.

## What's new

- **Calmer Tide dashboard:** verified protection is green **Active**; **Needs attention** is reserved for operational problems. Ordinary coverage limits live under expandable **Coverage details**, with a further technical disclosure for kernel and interface details. The status reads **Filtered where supported**, not universal protection.
- **Restore-after-reboot feedback:** visible **Enabling…** and **Disabling…** progress; the switch is guarded against duplicate taps, and only verified results are reported.
- **Simpler Insights recovery:** **Sample interrupted?** replaces the generic Troubleshooting section. **Check sample cleanup** retains the safe, narrowly scoped probe-recovery behavior, and detected leftover probes still receive a prominent alert.
- **Optional bundled Termux helper:** **Firewall → Termux quick commands → Install the helper → Copy installation command** supplies one command to run in normal Termux. The signed APK includes the read-only `pufw` helper; no separate download, shared-storage permission, or root access is needed *to install* it. The command verifies the helper's SHA-256 and atomically replaces an older copy only after successful extraction. Running `pufw` still requests root. Commands: `pufw`, `pufw tunnel`, `pufw stats` (separate physical/tunnel IPv4/IPv6 counters and bytes), and `pufw raw`. [Termux setup and limitations](https://github.com/wingetx/PocketUFW/blob/v0.1.0-beta8/docs/termux.md).
- **Quieter Settings:** neutral experimental-beta version footer and removal of a redundant Quick Settings explanation. The actual Quick Settings tile and long-press behavior are unchanged.

## Validation

- **393 Android JVM/Robolectric tests and 30 focused CLI/mock-kernel tests passed.** Lint: 0 errors, 3 existing warnings, 2 informational findings. The release APK builds successfully.
- The signed APK was verified using APK signature schemes v2/v3, with 16 KiB alignment and the same signing certificate as Beta7. All seven packaged privileged scripts were checked byte-for-byte against unchanged Beta7 source; the bundled helper matched its source SHA-256.
- Tested on a rooted **Pixel 9a, Android 17, Magisk 31.1**: signed APK updated in place, live physical rules remained **ACTIVE**, tunnel filtering **PINNED**, and address authorization **MATCH**. The new one-command installer ran successfully in **normal, rootless Termux**, replaced the previous helper, and `pufw` / `pufw stats` produced verified live status and per-family counters.
- The **full Python regression suite did not complete** during the independent run (timeout). Do not treat it as passed. Hardware coverage is limited; the results above are not proof of behavior on every Android device.

## Other limitations

- **ACTIVE means PocketUFW's rules and hooks were verified at inspection time, not guaranteed coverage of all traffic.** Earlier Android/OEM ACCEPT rules and unsupported interfaces can bypass PocketUFW's physical hooks.
- **PINNED uses verified destination addresses, not cryptographic origin authentication.** A different `tun*` interface may be able to inject traffic aimed at a pinned address. Optional tunnel filtering does not automatically restore after reboot; physical boot restoration is separate.
- **Insights is bounded, on demand, and diagnostic only.** It does not identify attackers or continuously monitor traffic. Android/OEM changes can safely prevent a sample.
- Automatic repair and background VPN monitoring are not implemented. Manually recheck and refresh when VPN listeners or Tailscale addresses change.
- Before uninstalling, use **Settings → Remove PocketUFW** to remove owned rules and boot hooks. A normal Android uninstall may otherwise leave live rules until reboot; slow boot can delay hook cleanup.

PocketUFW is experimental open-source software, **not** a replacement for Android's own security protections.
